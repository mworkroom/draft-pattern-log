## Decisions - Supabase 이중 백업

- 새 Supabase 프로젝트 대신 요청된 기존 `mworkroom`에 전용 테이블만 추가한다. 현재 목적은 추가 복구 경로이므로 통계·학생 모델 전체를 DB 중심으로 재설계하지 않는다.
- 앱과 같은 JSON 형식을 저장하고 공통 `parseBackup()`으로 검증·기존 필드 정규화를 적용한다. JSONB가 객체 키 순서를 바꾸므로 내용 비교는 키 순서와 무관하게 수행한다.
- 브라우저에는 자기 기록 조회만 허용하고, 백업 이력의 직접 수정·삭제는 허용하지 않는다. 소유자 결정·충돌 검사·이력 추가·최신 참조 이동은 인증 검사와 빈 search_path를 가진 단일 원자적 저장 함수에 한정한다.
- Supabase advisor가 확인한 참조 인덱스 누락과 RLS 함수 평가 문제는 후속 마이그레이션으로 해결했다. 로그인 사용자용 SECURITY DEFINER 실행 [경고](https://supabase.com/docs/guides/database/database-linter?lint=0029_authenticated_security_definer_function_executable)는 의도된 저장 API이며 소유권·익명 차단을 별도 검증했다. 새 인덱스의 unused-index 정보는 아직 실제 기록이 없는 초기 상태다. 기존 앱의 advisor 항목은 변경하지 않았다.
- 백업 버전은 자동 삭제하지 않고 UI에서 최근 50개를 표시한다. Supabase 안의 이력도 프로젝트·계정 삭제 시 소실될 수 있으므로 외부 JSON 백업을 함께 유지한다.
