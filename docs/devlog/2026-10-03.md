# 2026-10-03 Draft Pattern Log Development Log

## Work Summary

Background가 경력 단계와 고용 분야를 섞고 있어 별도 통계 분석이 어려웠다. Career Stage와 Sector를 독립적인 선택·저장·필터 차원으로 분리했다.

## Work Completed

- 폼의 Background를 Career Stage와 Sector 드롭다운으로 교체했다. 요청된 선택지와 순서를 적용하고 기본값은 모두 Not specified로 유지했다.
- 모델과 새 기록 저장, 편집 복원, JSON 백업, CSV를 두 독립 필드로 변경했다. CSV 열은 `career_stage`, `sector`이다.
- 공통 `parseBackup()` 경로에서 기존 localStorage, 수동 JSON 복원, 폴더 백업의 Background를 변환한다. Fresh Graduate는 Career Stage에만, Corporate/Public Sector/NGO/Other는 Sector에만 매핑한다. NGO는 NGO / Nonprofit으로 바꾸고 누락·빈 값·Not specified는 양쪽 빈 값으로 복원한다.
- Dashboard에 두 필터를 추가해 기존 지표, 수정 패턴, 리뷰 목록에 각각 적용한다. 두 필터 동시 선택도 지원한다.
- 1280px에서 긴 Career Stage 필터 선택지가 잘리는 것을 실제 글자 폭으로 확인했다. 필터 그리드를 최소 220px 기준 자동 줄바꿈으로 변경해 글자 크기를 유지했다.
- 모든 기존 Background 매핑, 새 값 우선 보존, 잘못된 값 거부, 백업 왕복, CSV 열, 독립·교차 필터와 수정 통계, 브라우저 저장·재편집·마이그레이션 검사를 추가·갱신했다.

## Decisions

- 두 값은 서로 유추하지 않는다. 기존 Background만으로 알 수 없는 차원은 Not specified이며, 합성 분류를 만들지 않는다.
- 기존 저장 키와 schemaVersion 1은 유지하고 읽기 시 정규화한다. 새 필드가 이미 있으면 빈 값까지 보존하며 Background로 덮어쓰지 않는다. 다음 저장·백업에는 Background를 제거한 두 필드가 기록된다.
- 경력 연수 기준은 코드 주석의 분류 지침으로만 남겼다. 폼에서는 요청된 명칭만 표시한다.
- 기존 Type 7 도움말 편집을 보존했다. 그 문구와 맞지 않던 단위·브라우저 테스트의 기대값을 현재 문구에 맞췄다.

## Current Status

- Chrome 100% 배율에서 2048×1152 및 1280×900 화면을 캡처·확인했다. 새 폼 입력 글자는 15px이며, 긴 선택지와 기본 동작에 잘림·겹침·문서 가로 넘침이 없었다. 화면 식별, 오류 오버레이 없음, 콘솔 오류 없음, 저장 후 재편집과 두 필터 적용을 확인했다.
- 초기 테스트·빌드는 샌드박스 상위 폴더 접근 제한으로 시작하지 못해 승인된 실행 경로로 재검증했다. 새 가독성 테스트는 필터 개수 배지가 버튼의 접근성 이름을 바꿔 시간 초과가 발생했고, 안정적인 버튼 선택자로 수정 후 두 화면 검사를 재실행해 통과했다.
- 변경은 로컬 작업 상태이며 커밋·푸시·배포는 하지 않았다. 실제 개인 데이터와 배포된 앱은 변경하지 않았다.

Type 4의 간접적·서사적 서술 특성을 더 정확하게 표현하도록 명칭과 설명을 갱신했다. 동일 학생의 여러 수정 차수를 이름에 섞지 않고 독립적으로 기록·분석할 수 있도록 Revision Round를 추가했다.

## Work Completed - Type 4 명칭 및 Revision Round

- Type 4를 `Type 4 — Narrative / Indirect`, 설명을 `핵심 의미를 늦추거나 숨기고, 극적 효과를 위해 우회적으로 서술`로 변경했다. 공통 표시 상수를 사용하므로 폼·필터·분포 통계가 함께 갱신된다.
- 입력·편집 폼의 학생 이름 옆에 Revision Round 1·2·3 선택 버튼을 추가했다. 새 기록의 기본값은 1이다.
- `revisionRound`를 숫자 1/2/3으로 저장하며 편집과 JSON 백업에 유지한다. CSV에는 `revision_round` 열을 추가했다.
- 기존 기록에 속성이 없을 때만 1로 정규화한다. 이미 저장된 차수는 보존하고 범위 밖 값·문자열·null은 백업 검증에서 거부한다.
- Recent Reviews와 Unclassified / New Pattern 목록의 이름 옆에 회색의 작은 2차·3차 배지를 추가했다. 1차에는 배지가 없고 이름 문자열 자체는 바꾸지 않는다.
- Dashboard의 Revision Round 필터로 총 건수, Problem Type 분포, 수정 통계, 최근 목록을 함께 좁힐 수 있다. 기존 Problem Type 필터와의 조합도 지원한다.

## Decisions - Type 4 명칭 및 Revision Round

- Type 4의 내부 키 `type4`와 기존 기록·CSV 지표는 그대로 유지했다. 새 유형이나 데이터 재분류를 만들지 않는다.
- Revision Round는 필수 숫자 메타데이터이며, Type 1–7의 판단·선택·검증 기준에는 영향을 주지 않는다. 각 차수는 별도 사례 기록으로 유지하며 학생 이름을 기준으로 자동 병합하거나 차수를 추측하지 않는다.
- 세 가지 선택은 기존 폼과 같은 분할 버튼으로 제공했다. 배지는 12px 보조 표시로 두어 14px 학생 이름이 주된 정보로 남도록 했다.
- 기존 저장 키와 schemaVersion 1을 유지하고 공통 `parseBackup()` 경로에 누락값 보정을 넣어 localStorage·수동 JSON·폴더 백업이 같은 규칙을 사용하도록 했다.
